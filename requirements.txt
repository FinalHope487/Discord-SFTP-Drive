# Keep this file ASCII-only. pip reads it with the locale encoding, so a
# non-ASCII character makes the install fail outright on non-UTF-8 consoles
# (cp950, cp1252, ...) before any package is resolved.
# Held one release short of 2.21.0, which added the sparse-file extension
# `ranges@asyncssh.com`. Its client asks for it by default on every get(), and
# its server side answers by calling lseek(SEEK_DATA) directly on whatever
# object is behind the handle -- reaching past every SFTPServer override this
# project has. Ours is a DiscordFile, which has no seek, so on Linux every
# download from an asyncssh client fails with "Uncaught exception". Windows is
# green either way: os.SEEK_DATA does not exist there, so asyncssh picks a
# different implementation and never seeks.
#
# The dangerous direction is the fix, not the bug. Under sparse=True a short
# copy is expected rather than an error, so a server that answers "no data
# here" produces a download that silently arrives as zeros. Moving past 2.20.0
# means teaching DiscordFile what its holes are, and that is a decision about
# the data path, not a version bump. See ROADMAP.md.
asyncssh==2.20.0
cryptography==50.0.0
motor==3.7.1
# Still pinned, but no longer to hold pymongo back: motor 3.7.1 declares
# >=4.9,<5 and imports fine against it. The pin exists because motor reaches
# into pymongo private names, so the pair has to be verified together rather
# than trusted from metadata -- "pip check" passes on combinations that fail
# at "import motor.motor_asyncio", which is how motor 3.4.0 + pymongo 4.9
# got in. Move both lines together, and prove it by importing, not by
# resolving.
pymongo==4.17.0
aiohttp==3.14.3
python-dotenv==1.2.2
# Argon2id for turning the SFTP password into the key that wraps the master
# key. PBKDF2-HMAC-SHA256 is still supported and still opens every record that
# was written with it -- the stored record names its own KDF -- but Argon2id is
# what new wraps use, because PBKDF2 is cheap to run on a GPU and Argon2id is
# deliberately memory-hard.
#
# This is the reference implementation rather than the one that landed in
# cryptography 44. The original reason was blast radius -- taking it from
# cryptography meant a two-major upgrade under asyncssh's transport layer.
# That reason expired when cryptography went to 50 here; the standing one is
# that swapping the KDF implementation touches how the master key is wrapped,
# which is its own decision and its own verification, not a side effect of a
# dependency bump. Ships manylinux and Windows wheels for cp311, so the image
# needs no build toolchain.
argon2-cffi==25.1.0
